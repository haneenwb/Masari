# التوثيق الفني — مساري

هذا المستند يشرح كيف يعمل التطبيق من الداخل، وكيف تُضاف إليه بيانات جديدة، وما القرارات الهندسية التي اتُّخذت ولماذا.

---

## 1. نظرة عامة على المعمارية

التطبيق **ملف واحد** (`index.html`) يحتوي على أربع طبقات مفصولة داخله:

```
┌──────────────────────────────────────────────┐
│ 1. الأنماط (CSS)                             │
│    متغيرات تصميم في :root + سمة داكنة        │
├──────────────────────────────────────────────┤
│ 2. الرموز والرسوم (SVG <defs>)               │
│    الشعار، الأيقونات، الرسوم التوضيحية        │
├──────────────────────────────────────────────┤
│ 3. البيانات والمنطق (JavaScript)             │
│    I18N · ENTITIES · ROLES · state · حسابات  │
├──────────────────────────────────────────────┤
│ 4. الواجهات (دوال v*)                        │
│    كل صفحة دالة تُرجع HTML كنص                │
└──────────────────────────────────────────────┘
```

**دورة الحياة:** حدث من المستخدم ← معالج مركزي مفوَّض (`document.addEventListener("click")`) ← تعديل `state` ← `save()` ← `render()` يعيد بناء الصفحة كاملة.

إعادة البناء الكاملة مقبولة هنا لأن حجم الشجرة صغير (أقل من ١٥٠٠ عقدة)، وتُبقي الواجهة دائمًا انعكاسًا مباشرًا للحالة بلا تزامن يدوي. الاستثناء الوحيد `refreshCV()` الذي يحدّث معاينة السيرة وحدها كي لا يفقد المستخدم مؤشر الكتابة أثناء التحرير.

### لماذا بلا إطار عمل؟
المشروع يُسلَّم كنموذج قابل للتشغيل فورًا وللتحقق من الفكرة. إطار عمل يعني مرحلة بناء واعتماديات ونشرًا أعقد، مقابل فائدة لا تظهر عند هذا الحجم. الانتقال إلى React + TypeScript مدرج في خارطة التطوير حين يظهر خادم خلفي وحسابات مستخدمين.

## 2. نموذج الحالة

```js
state = {
  consent: false,           // هل وافق المستخدم على الحفظ المحلي
  locale: "ar" | "en",
  theme:  "light" | "dark",
  step: 0..5,               // خطوة التقييم الحالية
  completed: false,         // أُنجز التقييم مرة واحدة على الأقل
  route: "home" | "path" | "analysis" | ... ,
  profile: {
    name, uni, field, major, year, gpa, gpaScale, gpaSkip,
    exp: "none"|"lt6"|"m6"|"y1"|"y2", coop: bool, courses,
    skills: { [skillId]: 0|25|50|75|100 },
    interests: [interestId],
    direction: "stay"|"transition"|"undecided",
    role: roleId,
    presence: { cv, li, pf },
    cvText, headline, summary, email
  },
  projects: [{ title, problem, approach, result, link, skills }],
  plan:     [{ id, phase, ar, en, mins, prio, due, dep, status, url }],
  picks:    { skills: [skillId], orgs: [entityId] },
  filters:  { q, type, cost, format }
}
```

**التخزين:** مفتاح واحد `masari.v2` في `localStorage`. لا يُكتب شيء قبل أن تصبح `consent` صحيحة. الدالة `migrate()` تقرأ مفتاح النسخة السابقة `masar.v1` وتحوّل مستويات المهارات القديمة (0/1/2) إلى النسب الجديدة، فلا يفقد مستخدم سابق ملفه.

**الحذف:** `wipe()` تمسح المفتاحين معًا وتعيد الحالة إلى `BLANK`، وتحافظ على اللغة والسمة فقط حتى لا تنقلب الواجهة فجأة أمام المستخدم.

## 3. المعادلات

كل الدوال أدناه **نقية**: تأخذ الحالة وتُرجع رقمًا، بلا آثار جانبية، وقابلة للاختبار مباشرة.

### 3.1 نسبة الملاءمة — `matchScore(role)`

```
تغطية المهارات = مجموع مستويات مهارات الدور ÷ (عدد المهارات × 100)
قرب المجال     = 1.00  إذا كان مجال الدور = المجال الأكاديمي
                 0.55  إذا أعلن المستخدم رغبته في الانتقال لمجال آخر
                 0.35  فيما عدا ذلك
توافق الاهتمام = نسبة تقاطع وسوم الدور مع اهتمامات المستخدم (0.5 عند غياب الوسوم)

الملاءمة = (0.60 × التغطية + 0.25 × قرب المجال + 0.15 × توافق الاهتمام) × 100
```

الأوزان في الثابت `WEIGHTS`، والمعادلة معروضة للمستخدم نصًا في صفحة المسار تحت «كيف حُسبت الملاءمة».

### 3.2 فجوة المهارات — `gapOf(role)`

| المستوى | التصنيف |
|---|---|
| 75–100 | متوفرة (`have`) |
| 25–50 | تحتاج تطوير (`dev`) |
| 0 | ناقصة (`dev`) |
| أقل من 50 **ومهارة أساسية** (`core: true`) | أولوية عالية (`prio`) — تدخل الخطة أولًا |

### 3.3 جاهزية الملف

```
جاهزية السيرة (ATS) = بنود المراجعة المجتازة ÷ 6 × 100
   البنود: دور محدد · ثلاث مهارات مسماة · نبذة > 40 حرفًا ·
           تعليم كامل · خبرة أو تدريب · مشروع واحد

لينكدإن = البنود المجتازة ÷ 4 × 100   (عنوان، نبذة، مهارات، خبرة)
معرض الأعمال = min(100, عدد المشاريع × 40 + 20 إن وُجد رابط)

الجاهزية الكلية = 0.45 × السيرة + 0.30 × لينكدإن + 0.25 × المعرض
```

### 3.4 تحليل القوة والضعف — `swot()`

محرك قواعد يفحص الحالة ويُخرج قائمتين. كل بند يحمل: أيقونة، عنوانًا، **دليلًا مستخرجًا من بيانات المستخدم**، ووجهة تعالجه.

أمثلة على القواعد:

| الشرط | الناتج |
|---|---|
| `have.length ≥ 2` | قوة: أساس مهاري متين + أسماء المهارات وعددها |
| `role.field === profile.field` | قوة: التخصص في صميم الدور |
| `prio.length > 0` | ضعف: مهارات أساسية دون النصف + أسماؤها |
| `exp === "none" && !coop` | ضعف: لا خبرة ولا تدريب، مع توجيه إلى صفحة الفرص |
| `cvScore() < 70` | ضعف: السيرة ناقصة + أول بند مراجعة فاشل |
| عدد البنود المتأخرة ≥ 3 | ضعف: بنود تجاوزت موعدها، مع دعوة لإعادة الجدولة لا للوم |

**قاعدة الصياغة:** كل بند ضعف يذكر السبب والإجراء، ولا يحمل حكمًا على المستخدم. المنتج يخاطب أشخاصًا في وضع ضاغط، والنبرة جزء من المتطلبات لا من التجميل.

### 3.5 توليد الخطة — `buildPlan()`

يأخذ المهارات المختارة (أو أعلى أربع فجوات إن لم يختر المستخدم) ويولّد بنودًا موزّعة على أربع مراحل:

| المرحلة | المحتوى |
|---|---|
| 01 الأساسيات | مسودة السيرة إن لم توجد + أساسيات أول مهارة |
| 02 المهارات التقنية | تعلّم كل مهارة + تطبيقها على بيانات حقيقية + متابعة الجهات المختارة |
| 03 معرض الأعمال | بناء مشروع واحد + إضافته للمعرض (يعتمد على سابقه) |
| 04 جاهز للتقديم | لينكدإن + تحديث السيرة + خمس رسائل تواصل + استعراض عَتَبة + التقديم |

كل بند: `mins` (وقت متوقع)، `prio` (أولوية)، `due` (موعد تراكمي بالأسابيع)، `dep` (اعتماد على بند سابق)، و`url` اختياري لبنود تحتاج مصدرًا خارجيًا.

## 4. نزاهة البيانات

نوع السجل المستخدم لكل جهة:

```js
{
  id, nameAr, nameEn, type,
  status: "placeholder" | "verified",
  sourceUrl: string | null,     // إلزامي عند verified
  verifiedAt: "YYYY-MM-DD" | null,
  cost:   { type: "free"|"paid"|"unknown", amountSar: number|null },
  format: "online"|"in_person"|"hybrid"|"unknown",
  purposeAr, purposeEn            // null عند placeholder
}
```

**قاعدة العرض المطبَّقة في `vOpps()`:** السجل `placeholder` يُعرض باسمه وشارة «بيانات تجريبية» فقط. لا سعر، لا شرط، لا رابط، لا موعد. السجل `verified` وحده يعرض وصفه وروابطه وتاريخ تحققه.

حاليًا سجل واحد متحقق: **عَتَبة** (`https://3atabah.com`، تاريخ التحقق 2026-09-02). إجراء التحقق الكامل في [DATA_SOURCES.md](DATA_SOURCES.md).

## 5. الترجمة والاتجاه

- كل النصوص في كائن `I18N` بمفتاحي `ar` و`en`، ولا يوجد نص مكتوب داخل الواجهات.
- الدالة `t("path.to.key")` تقرأ بالمسار وتُرجع المفتاح نفسه عند غيابه — ما يجعل أي مفتاح مفقود ظاهرًا فورًا أثناء المراجعة.
- `document.documentElement.dir` و`lang` يتغيران مع اللغة، والأنماط تستخدم **الخصائص المنطقية حصرًا** (`inset-inline-start`، `margin-inline`، `padding-inline`) بلا `left/right`.
- الأيقونات الاتجاهية (السهم) والرسوم ذات المعنى الاتجاهي (المسارات، الجسر) تنعكس بالصنف `.flip-dir`؛ الأيقونات غير الاتجاهية لا تنعكس.
- **الأرقام لاتينية في اللغتين** عبر `ar-SA-u-nu-latn`، لأن السير الذاتية وبوابات التوظيف السعودية تستخدمها، فتتطابق الواجهة مع ملفات المستخدم. السنوات تستخدم منسّقًا بلا فاصلة آلاف (`yf`)، والأرقام في البطاقات تستخدم أرقامًا جدولية (`tnum`).

### فحص اكتمال الترجمة

```bash
# يستخرج كل مفاتيح t("...") من الكود ويتأكد من وجودها في العربية والإنجليزية
node -e '
const fs=require("fs"); const s=fs.readFileSync("index.html","utf8");
const i=s.indexOf("const I18N = {"), j=s.indexOf("/* ------------------------- data");
eval(s.slice(i,j).trim().replace(/;$/,""));
const keys=[...new Set([...s.matchAll(/\bt\("([a-zA-Z0-9_.]+)"\)/g)].map(m=>m[1]))];
const get=(o,p)=>p.split(".").reduce((a,k)=>a&&a[k],o);
const bad=keys.flatMap(k=>["ar","en"].filter(l=>get(I18N[l],k)===undefined).map(l=>l+":"+k));
console.log(bad.length?"مفاتيح ناقصة: "+bad.join(", "):"جميع المفاتيح مكتملة في اللغتين");'
```

## 6. نظام التصميم

المتغيرات كلها في `:root` مع نسختين للسمة الداكنة (`prefers-color-scheme` و`[data-theme="dark"]`).

| الفئة | المتغيرات |
|---|---|
| الهوية | `--brand` مرجاني · `--brand-pill` خوخي · `--gold-tint` كريمي · `--nav` كحلي داكن |
| الأسطح | `--bg` · `--card` · `--card-2` · `--line` · `--line-2` |
| النص | `--text` · `--muted` |
| الحالات | `--ok` أخضر داكن · `--warn` · `--bad` |
| الأشكال | `--r-s` 6 · `--r-m` 8 · `--r-l` 12 · `--r-xl` 16 · الأزرار حبّات 9999 |

**قواعد ثابتة:** لون الفعل واحد ولا يُستخدم للنص، والتحذير يبقى بلون مختلف عن الهوية كي لا يذوب فيها، والعناوين بوزن 300 مع تباعد سالب **على اللاتيني فقط** — التباعد السالب يشوّه الحروف العربية المتصلة.

الرسوم كلها SVG داخل الصفحة تستخدم `var(--...)` فتتبع السمة تلقائيًا. مواضع التصوير البشري مهيّأة في الكائن `PHOTOS` (`hero`، `linkedin`، `learning`): عند وضع ملف WebP بمقاسين مع `width/height` يستبدل التصوير الرسم تلقائيًا بتحميل كسول وبلا إزاحة تخطيط.

## 7. الإتاحة

- تنقل كامل بلوحة المفاتيح مع `:focus-visible` بحلقة ظاهرة بسمك 2.5 بكسل
- `aria-current="page"` على عنصر التنقل النشط، و`role="dialog"` و`aria-modal` على النوافذ
- `role="alert"` على رسائل الخطأ في التقييم، و`role="status"` على الإشعارات
- الرسوم ذات المعنى تحمل `role="img"` و`aria-label` وصفيًا؛ الزخرفية `aria-hidden`
- `@media (prefers-reduced-motion: reduce)` يوقف كل الحركات والانتقالات
- تباين النص الأساسي فوق 4.5:1 في السمتين

## 8. دليل التوسعة

### إضافة مسار وظيفي

```js
// في مصفوفة ROLES
{
  id:"product-owner", field:"biz",
  ar:"مالك منتج", en:"Product Owner",
  tags:["i-tech","i-people"],                 // تُستخدم في حساب توافق الاهتمامات
  skills:[
    S("backlog","إدارة قائمة العمل","Backlog management", true),  // true = مهارة أساسية
    S("ux","أساسيات تجربة المستخدم","UX fundamentals"),
  ]
}
```
لا يلزم أي تعديل آخر: البطاقة في الصفحة الرئيسية، والملاءمة، والفجوة، والخطة تُشتق كلها من هذا السجل.

### إضافة جهة

```js
P("new-org","الاسم بالعربية","English name","academy")   // سجل تجريبي
```
لتحويله إلى متحقق: راجع [DATA_SOURCES.md](DATA_SOURCES.md) وأضف `sourceUrl` و`verifiedAt` و`purposeAr/En` وغيّر `status`.

### إضافة نص للواجهة
أضف المفتاح في `I18N.ar` و`I18N.en` معًا، واستدعه بـ `t("...")`. لا تكتب نصًا داخل دوال العرض.

### إضافة صفحة
1. اكتب دالة `vNewPage()` تُرجع HTML نصًا
2. سجّلها في `VIEWS`
3. أضفها إلى `NAV_MAIN` أو `NAV_BUILD` أو `NAV_ACCT` مع أيقونتها
4. أضف `nav.newpage` في اللغتين

## 9. قائمة الفحص قبل التسليم

لا توجد اختبارات آلية في هذه النسخة، والمراجعة تتم يدويًا وفق هذه القائمة:

**الوظائف**
- [ ] التقييم يكتمل من الخطوة الأولى إلى السادسة، وتظهر نافذة الموافقة قبل أول حفظ
- [ ] البيانات تبقى بعد إعادة تحميل الصفحة، وتُمسح كاملة عند «حذف بياناتي»
- [ ] رفع PDF وDOCX، والتحقق من ظهور البديل اليدوي عند فشل القراءة
- [ ] بناء الخطة، تغيير حالة المهام، وانعكاس ذلك على شريط التقدم ومهام اليوم
- [ ] طباعة السيرة: عمود واحد، نص قابل للتحديد، بلا قائمة جانبية ولا أزرار

**اللغة والاتجاه**
- [ ] تبديل اللغة على كل صفحة، مع انعكاس التنقل والأسهم والرسوم الاتجاهية
- [ ] فحص اكتمال الترجمة (الأمر في القسم 5) بلا مفاتيح ناقصة

**الاستجابة**
- [ ] 360 و768 و1280 بكسل: القائمة الجانبية تصبح شريطًا سفليًا، ولا نص متداخل، ولا تمرير أفقي للصفحة

**الإتاحة**
- [ ] المرور بلوحة المفاتيح على كل عنصر تفاعلي مع حلقة تركيز ظاهرة
- [ ] السمة الداكنة والفاتحة معًا

**نزاهة البيانات**
- [ ] كل سجل `placeholder` بلا سعر ولا رابط ولا شرط ولا موعد
- [ ] كل سجل `verified` له `sourceUrl` و`verifiedAt` حقيقيان
- [ ] لا اسم شخص طبيعي في أي مكان في المستودع
